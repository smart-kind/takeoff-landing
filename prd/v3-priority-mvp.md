# Takeoff & Landing — PRD v3

> 版本：v3 · 2026-08-19
> 主题：功能优先级 + MVP 范围界定
> 状态：迭代中

---

## 1. 一句话定位

**Takeoff & Landing**：给非 PM 用户的"傻瓜式产品经理"平台——把模糊想法变成可执行方案（起飞），把写好的代码变成可访问的产品（落地）。

---

## 2. 核心问题陈述

有了 AI 之后，开发不再是瓶颈。真正的瓶颈在两头：
1. **起飞**：产生合适的创意 + 规划成可实施的路径
2. **落地**：备案、域名、小程序认证、收款……跟真实世界打交道的事

中间的开发过程，AI 几乎可以完全替代。

---

## 3. 目标用户画像

### Persona A：资深开发者转产品（"技术型创客"）

**典型特征**：
- 开发经验 10-20 年，技术能力强
- 想做产品但缺乏系统化的产品思维
- 知道有 PRD、优先级框架这些概念，但不知道什么时候用、怎么用
- 有 77 个 PM skill 摆在面前也不知道从哪下手

**痛点**：
- "我知道有很多方法论，但我不知道该用哪个"
- "让我转变成产品经理太难了，合适的时机使用合适的技巧极难"

**期望**：
- 有人告诉他"你现在只需要做这 3 件事"
- 不需要懂专业 PM 术语

### Persona B：独立开发者 / 创业者

**典型特征**：
- 有技术能力，想做出自己的产品
- 有想法但不知道如何变成可执行的方案
- 一个人就是一个团队

**痛点**：
- 不知道第一件该做什么
- 做了东西但不知道如何部署上线
- 备案、域名、收款这些流程没人教

**期望**：
- 从想法到上线有一条清晰的路
- 不需要学 PM 理论，照着做就行

### Persona C：产品经理学习者

**典型特征**：
- 想成为 PM，或者想系统学习产品方法论
- 被 77 个 skill 吓到，不知道从何学起

**痛点**：
- 知识太多，没有路径
- 学了理论但不知道怎么用

**期望**：
- 在做真实项目的过程中学习 PM 方法

## 4. 使用场景

### 场景 1：从想法到可执行方案（起飞）

用户创建项目 → 输入模糊想法 → 系统分析状态 → 输出"现在只需要做这 3 件事" → 用户跟着引导逐步完成 → 系统维护一致数据源。

### 场景 2：从代码到可访问产品（落地）

用户标记进入"落地"阶段 → 系统根据目标市场给出路径 → 逐步引导：域名 → 备案 → 小程序上架 → 支付接入 → 部署。

### 场景 3：边做边学

用户选择真实项目 → 系统在每一步适时展示背后的 PM 方法论 → 实际操作中学习。

## 5. Jobs to Be Done

| 用户想完成的工作 | 当前替代方案 | 不满意的原因 |
|-----------------|-------------|-------------|
| 把我的模糊想法变成可执行方案 | 自己查资料、问 ChatGPT | 信息太多太杂，不知道用哪个 |
| 知道我现在最该做什么 | 凭直觉或模仿别人 | 没有系统化的引导 |
| 把写好的代码变成可访问的产品 | 到处搜教程 | 每个教程只覆盖一个环节，缺整合 |
| 在实际项目中学 PM 方法 | 看 PM 书籍 / 上课 | 理论脱离实践 |

## 7. 功能全景与优先级

本版本基于 **prioritization-advisor** 和 **roadmap-planning** 方法论，对所有候选功能进行系统优先级排序，并界定 MVP 边界。核心原则：**对用户来说不需要知道什么叫 RICE 或 ICE——系统直接在后台完成排序，呈现为"先做这些"。**

### 7.1 功能清单（全部候选）

| 编号 | 功能模块 | 所属阶段 | 说明 |
|------|---------|---------|------|
| F01 | 项目工作空间 | 起飞 | 创建、编辑、保存项目 |
| F02 | 一致数据源 | 起飞 | 项目所有草稿/笔记/决策关联存储 |
| F03 | Skill 导航引擎 | 起飞 | 根据项目状态自动推荐下一步 |
| F04 | 优先排序 | 起飞 | 只显示当前最该做的 1-3 件事 |
| F05 | PRD 自动生成 | 起飞 | 引导用户完成 PRD 草稿 |
| F06 | 项目状态追踪 | 起飞 | 记录项目完成了哪些阶段 |
| F07 | PM 知识卡片 | 起飞 | 在步骤中适时展示方法论原理 |
| F08 | 模板库 | 起飞 | 预置的 PRD、用户故事等模板 |
| F09 | 域名注册指南 | 落地 | 国内外域名选择与注册流程 |

### 7.2 优先级排序逻辑

系统内部使用多维度评分（参考 RICE + Kano 框架，但对用户完全透明）：

| 维度 | 说明 | 权重 |
|------|------|------|
| 用户价值 | 是否直接解决核心痛点（"不知道从哪下手"） | 高 |
| 实现难度 | 技术复杂度、依赖项数量 | 中 |
| 依赖关系 | 是否有前置功能必须完成 | 高 |
| 差异化 | 是否是竞品难以复制的核心能力 | 中 |

## 8. MVP 范围界定

### 8.1 MVP 定义原则

- **最小**：能验证核心假设的最少功能集合
- **可用**：用户能完整走完"起飞"流程
- **有价值**：用户能明显感受到"比我自己瞎摸索好太多"

**MVP 的核心假设**：非 PM 用户在使用引导后，能够在 30 分钟内从一个模糊想法产出一份结构化的可执行方案。

### 8.2 MVP 功能清单

MVP 包含 **6 个 P0 功能** + **2 个 P1 功能**：

| 功能 | 归属 | MVP 范围说明 |
|------|------|-------------|
| F01 项目工作空间 | 起飞 | 创建项目 + 基础编辑 + 保存 |
| F15 用户注册/登录 | 通用 | 邮箱注册 + 密码登录（最简方案） |
| F02 一致数据源 | 起飞 | 项目内部所有内容的结构化存储 |
| F03 Skill 导航引擎 | 起飞 | 基于项目状态的"下一步"推荐（至少覆盖 3 个阶段） |
| F04 优先排序 | 起飞 | 每次只显示 1-3 件事，附"为什么" |
| F05 PRD 自动生成 | 起飞 | 引导式问答 → 自动生成 PRD 草稿 |
| F06 项目状态追踪 | 起飞 | 记录已完成步骤，驱动导航引擎 |
| F19 新手引导 | 通用 | 首次使用的 3 步引导流程 |

### 8.3 MVP 不包含什么（明确排除）

| 排除项 | 原因 | 预计加入版本 |
|--------|------|-------------|
| 落地模块（域名/备案/支付等） | 不是验证核心假设的必要条件 | v4-v5 迭代 |
| PM 知识卡片 | 增强体验，不解决核心问题 | v5 |
| 模板库 | PRD 自动生成可先用内建模板 | v5 |
| 多人协作 | 初期用户以个人为主 | v7+ |
| 仪表盘 | 单个项目阶段不需要 | v5 |
| 数据导出 | 不影响核心流程 | v4 |

### 8.4 MVP 成功标准

| 指标 | 目标 | 测量方式 |
|------|------|---------|
| 用户能在 30 分钟内完成从想法到 PRD 草稿 | ≥ 70% 首次用户 | 埋点计时 |
| 用户认为"比我自己做快" | ≥ 80% 用户评价 | 使用后的即时问卷 |
| 用户愿意再次使用 | ≥ 50% 返回率 | 7 天内回访 |
| 导航引擎推荐准确率 | 用户采纳率 ≥ 60% | 步骤完成率 |

### 8.5 MVP 用户旅程（简化版）

```
注册 → 创建项目 → 输入模糊想法
       ↓
导航引擎分析状态 → 推荐"现在做这 3 件事"
       ↓
跟随引导完成 ①问题定义 → ②需求验证 → ③PRD 草稿
       ↓
查看生成的 PRD → 导出或继续完善
```

**总步数**：约 10-15 步，全程不超过 30 分钟。

## 9. 迭代节奏建议

| 阶段 | 时间 | 目标 |
|------|------|------|
| **Phase 0（第 1-2 周）** | 基础设施 | 用户系统 + 项目 CRUD + 数据存储 |
| **Phase 1（第 3-4 周）** | 核心引擎 | Skill 导航引擎 v1 + 优先排序逻辑 |
| **Phase 2（第 5-6 周）** | PRD 生成 | 引导式问答 + PRD 模板 + 自动生成 |
| **Phase 3（第 7-8 周）** | 体验打磨 | 新手引导 + 状态追踪 + Bug 修复 |
| **Alpha 内测（第 9 周）** | 验证 | 邀请 10-20 人内测，收集反馈 |

## 10. 核心价值主张

**对用户**：
- 不需要学 PM 理论，就能做出好产品
- 不需要搜几十个教程，就有一条完整的路
- 从想法到上线，一个平台搞定

**对 PM 方法论的价值**：
- 让 77 个 PM skill 真正被用起来
- 通过"skill on skill"的方式，让方法论在后台自动应用
