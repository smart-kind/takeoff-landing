## 8. 技术架构选型

### 8.1 架构原则

| 原则 | 说明 |
|------|------|
| **本地优先** | 用户数据优先本地存储，减少云端依赖 |
| **AI 可替换** | 不锁死任何一个 LLM 提供商，支持 Ollama + 云端双模式 |
| **渐进式复杂度** | 从单文件存储开始，需要时迁移到数据库 |
| **Electron 兼容** | 前端架构考虑后续 Electron 包装，不依赖浏览器特有 API |

### 8.2 技术栈选型

#### 前端

| 方案 | 选择 | 理由 |
|------|------|------|
| **React + Next.js** | ✅ 采用 | SSR 有利于 SEO、路由成熟、Electron 兼容好 |
| Vue + Nuxt | ❌ 备选 | 团队熟悉度未知 |
| 纯静态 + htmx | ❌ 不选 | 交互复杂度不够 |

**具体技术**：
- Next.js 15（App Router）
- TypeScript
- Tailwind CSS
- shadcn/ui（组件库）
- Zustand（状态管理，轻量）

#### 后端

| 方案 | 选择 | 理由 |
|------|------|------|
| **FastAPI (Python)** | ✅ 采用 | AI 生态最好、Python 写 prompt 工程方便、异步原生 |
| Node.js + Express | ❌ 备选 | AI 集成不如 Python 生态成熟 |
| Go | ❌ 不选 | 开发速度不够快 |

**具体技术**：
- FastAPI
- Pydantic（数据校验）
- SQLAlchemy（ORM）
- LangChain / LiteLLM（LLM 抽象层）

#### 存储

| 方案 | 选择 | 理由 |
|------|------|------|
| **SQLite（开发/小型部署）→ PostgreSQL（生产）** | ✅ 采用 | 开发零配置，SQLite 单文件存储天然适合本地优先 |
| MongoDB | ❌ 不选 | 数据模型偏关系型，不需要文档数据库 |

#### AI 集成

| 组件 | 方案 | 说明 |
|------|------|------|
| **LLM 抽象层** | LiteLLM | 统一接口，支持 OpenAI/Anthropic/Ollama/DeepSeek |
| **本地 LLM** | Ollama | Docker 部署，支持 Qwen、Llama 等模型 |
| **云端 LLM（备用）** | OpenAI / Anthropic / DeepSeek | 可配置，用户自行填入 API key |
| **Embedding** | 本地 SentenceTransformers + 云端备用 | 语义搜索用 |
| **Skill 引擎** | 自研 | 基于 SKILL.md 格式的解析 + 状态机路由 |

#### 部署

| 环境 | 方案 |
|------|------|
| **开发** | Docker Compose（前端 + 后端 + SQLite + Ollama） |
| **生产（初期）** | VPS + Docker（阿里云/腾讯云） |
| **生产（后期）** | K8s 或 Serverless |
| **桌面版** | Electron 包装（前端用 Tauri 也行，更轻量） |

### 8.3 系统架构图

```
┌─────────────────────────────────────────────────────┐
│                   用户浏览器 / Electron              │
│                     Next.js 前端                     │
└───────────────────────┬─────────────────────────────┘
                        │ HTTP / REST API
┌───────────────────────▼─────────────────────────────┐
│                   FastAPI 后端                       │
├──────────────┬──────────────┬───────────────────────┤
│ 项目管理服务  │ Skill 导航   │ 落地指南服务          │
│              │ 引擎         │                       │
├──────────────┼──────────────┼───────────────────────┤
│   LLM 网关   │  文档生成    │  用户认证（v1.1）      │
│  (LiteLLM)   │  引擎        │                       │
└──────┬───────┴──────┬───────┴───────────┬───────────┘
       │              │                   │
┌──────▼──────┐ ┌─────▼──────┐  ┌────────▼────────┐
│  SQLite /   │ │  Ollama /  │  │  本地文件系统    │
│  PostgreSQL │ │  Cloud LLM │  │  (草稿/导出)     │
└─────────────┘ └────────────┘  └─────────────────┘
```

### 8.4 关键决策

| 决策 | 选择 | 替代方案 | 原因 |
|------|------|----------|------|
| 是否用数据库 | SQLite 起步 | 直接上 PostgreSQL | 单用户场景 SQLite 够用，迁移成本低 |
| 是否自研 Skill 引擎 | 自研 | 直接用现有框架 | 需要"skill on skill"的元层，现有框架不匹配 |
| 是否支持离线 | 是（本地 LLM） | 纯云端 | 用户隐私优先，本地模型可用时不上传 |
| Electron or Tauri | Tauri | Electron | Tauri 更小更快，Rust 后端可与 FastAPI 互补 |
